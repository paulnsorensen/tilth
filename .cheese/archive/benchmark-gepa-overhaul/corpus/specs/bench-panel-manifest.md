## Problem

Parent goal: Grow the benchmark with FeatureBench, the Gin render-context task, and a few cherry-picked tasks, in a format GEPA can optimize against once-run stored baselines, with a model judge for structural-tool applicability.

This curd ships the panel for G-1, G-2, and G-3 and closes parent AC-1. At c1 commit `806ea7b`, `run.py` selects tasks only by a comma list or `all` over the in-process `TASKS` dict (`benchmark/run.py:1277-1281,1341`, `benchmark/tasks/__init__.py:80-147`), optionally filtered by repo (`benchmark/run.py:1396-1401`). Nothing names a fixed task set, nothing separates tasks an optimizer may learn from and tasks held out for the final score, and nothing stops that set from changing after results exist. External tasks from c2 are not in `TASKS`, so `run.py` cannot select them at all.

## Contract

The panel manifest (parent curd c3) changes only the benchmark harness. Line citations below are at c1 commit `806ea7b` unless marked otherwise.

- **Panel file (F-1).** `benchmark/panels/<name>.json` is a JSON object with `name`, `split_seed` (integer), and `members`. Each member has `id`, `family` (`local`, `featurebench`, or `swebench_ml`), `language`, and `split` (`cheap`, `dev`, or `test`). A `swebench_ml` member that replaces a primary also has `fallback_for` and `fallback_reason`. Unknown keys, unknown `family` values, and duplicate ids are refused, following the `_unknown_keys` pattern of `load_experiment` (`benchmark/variants.py:45-48,51-113` at `4cafeea`).
- **Required members (G-1, G-2, G-3).**
  - `local`: exactly `rg_search_dispatch`, `rg_trait_implementors`, `gin_servehttp_flow`, and `gin_edit_render_context`, each resolved from `TASKS` (`benchmark/tasks/__init__.py:98,100,119,126`), with repo languages from `REPOS` (`benchmark/config.py:101,110-140`).
  - `swebench_ml`: exactly one Go slot member and one Rust slot member. The Go slot is `gin-gonic__gin-3741` or its fallback `prometheus__prometheus-14861`. The Rust slot is `sharkdp__bat-2650` or its fallback `tokio-rs__tokio-6724`. Instances are taken at HF revision `846e647b` per the parent minor decisions. Any other `swebench_ml` id is refused.
  - `featurebench`: at least one member, each a FeatureBench Lite Level 1 instance id.
  - Any other member is refused.
- **Languages.** Language is a stratification sort key, so it is never free text. A `featurebench` member must declare `python`. A Go slot member must declare `go` and a Rust slot member `rust`. Every external member's declared language must equal `external.language_of(row)`, a pure c2 seam applied to that instance's dataset row. A local member must equal its repo language in `REPOS`. Any mismatch is refused, so a declared language cannot steer the dev and test assignment.
- **Fallback recording.** A fallback member carries `fallback_for` naming its slot primary from the fixed pair table above and a non-empty `fallback_reason` that records why the primary was not admitted (the primary's preflight reason). A slot holding both its primary and its fallback, neither, or a fallback paired with the wrong primary is refused. The loader does not re-run the primary's preflight [AGENT-DECIDED: alternative is to call `external.preflight.admit` on the primary and refuse the fallback when the primary admits].
- **Tiers.** The three local hard tasks form the cheap tier. They are dev-only and carry `split: cheap`. No other member may be `cheap`. `Panel.cheap` is that tier. `Panel.dev` and `Panel.test` hold the remaining members.
- **Stratification [AGENT-DECIDED: alternative is strata keyed by family and language, which leaves single-member strata and an empty test split when only one FeatureBench task is admitted].** Strata are source families over the non-cheap members (`local`, `featurebench`, `swebench_ml`). Inside a stratum, members are sorted by `(language, sha256("<split_seed>:<id>"))` and assigned alternately `dev`, `test`, `dev`, and so on, so dev gets the extra member of an odd stratum and the Go and Rust SWE-bench Multilingual members always land on opposite sides. With the required members this puts `gin_edit_render_context` in dev and the Rust slot member in test, so the test split is never empty. `panels.stratify` computes this assignment. `load_panel` refuses a file whose recorded `dev` and `test` assignment differs from `stratify(members, split_seed)`, so a hand-picked split cannot be committed.
- **Split digest.** `split_digest` is the sha256 of the canonical JSON (sorted keys, no whitespace) of `{"cheap": [...], "dev": [...], "test": [...]}` with each list sorted by id. Member order in the file and member fields outside the split (such as `fallback_reason` text) do not change it. Any change to an id list, including swapping a fallback in for a primary, changes it.
- **One enforcement point (F-1).** `panels.load_panel(path, *, store_path, admit=external.preflight.admit, row_source=None)` is the only way to obtain a `Panel`. It raises `PanelError` on any schema, family, language, fallback, tier, or stratification fault, on any missing required member, on any non-admitted external member, and on a changed split. `store_path` is the c1 store file. Every caller passes the one `run.py` writes, `RESULTS_DIR / baselines.STORE_FILENAME` (`benchmark/run.py:1474`), and tests pass a temp path. `row_source(instance_id)` returns the dataset row for the language check. By default c3 reads the full cached row that c2 keeps in `$TILTH_BENCH_DATA`. Callers include `run.py --panel` and c5 `evolve.main`, which already loads the panel through `panels.load_panel` (`bench-evolution-loop.md` Approach step 1). c5 must not build a panel any other way and must pass the same store path.
- **Completeness and admission (F-1).** `load_panel` refuses a panel that lacks any required member. It calls `admit(instance_id)` for every `featurebench` and `swebench_ml` member and refuses when any verdict's `admitted` is false. The refusal names each missing or unadmitted member and carries the verdict `reason`. A non-admitted member is never dropped silently, because dropping it would change the split. c2's own pre-cell guard in `run.py` obtains its verdicts by calling the same cached `external.preflight.admit()`. That is the seam c3 relies on, so stubbing `admit` in a test covers both the panel check and c2's guard.
- **Registration (F-1).** `Panel.register(tasks: dict)` loads each external member through `external.featurebench.load` or `external.swebench_ml.load` and inserts it into the given `TASKS` dict under its task name. `run_single`, `_run_single_in_repo`, and `cell_identity` look tasks up there (`benchmark/run.py:648,704,743`). Registration is idempotent. Re-registering the same instance id whose c1 task digest is unchanged is a no-op; the digest is the one `run._cell_task_digest` computes (`benchmark/run.py:621-634`), imported inside `register` to avoid an import cycle. A different task under an existing name, including a local `TASKS` name, is refused. Both `run.py --panel` and c5 `run.run_plan` call it, so evolve can register the panel once per candidate in one process.
- **Run wiring (F-1).**
  - `run.py --panel PATH` calls `load_panel` and then `panel.register(TASKS)` before the MCP preflight and before any runner call. `--panel-split {cheap,dev,test,all}` (default `all`) picks the members to run. `--panel` with a non-default `--tasks` or `--repos` is a parser error.
  - Local-repo validation and cleaning (`benchmark/run.py:1424-1438`) apply to local members only; c2's `prepare` hook owns external checkouts.
  - No panel code path starts a container. External cells run natively through c2's `prepare` and grading hooks (F-1).
- **Row stamp.** `Panel.stamp(task_name)` returns `{panel_name, panel_split_digest, panel_split}`. `panel_name` is the manifest `name`, `panel_split_digest` is the panel's `split_digest`, and `panel_split` is that member's tier (`cheap`, `dev`, or `test`). On the `run.py` path, the stamp joins the per-cell `experiment_metadata` (`benchmark/run.py:1570-1575`). That metadata already reaches three places: the reused output copy (`:1580`), the failure row (`:1611` then `baselines.store` at `:1557`), and the fresh row (`:1629` then `baselines.store` at `:1644`). So every stored row and every output copy carries the stamp, applied before store. The stamp fields are not run-key inputs, so a split change does not invalidate stored rows. A reused row's output copy carries the current stamp; the stored row keeps its original stamp.
- **run_plan seam (defined by c3, implemented and tested by c5).** `run.run_plan(cells, *, panel: Panel, ledger, candidate_sha, refreeze_baselines)` takes a required `panel`, calls `panel.register(TASKS)`, and merges `panel.stamp(task_name)` into each row before `baselines.store` on the same store path. c3 fixes the `Panel.stamp` and `Panel.register` contracts and stamps on the `run.py` path. c5 owns `run_plan` and its stamping test, so rows that evolve stores carry the stamp and the split lock engages for evolve-only results.
- **Store read (c3-added seam on c1).** c3 adds `baselines.rows(path, *, panel_name: str | None = None) -> Iterator[Row]` to c1's `benchmark/baselines.py`. Like c1's `load_rows(path)`, `lookup(key, *, path)`, and `store(row, *, path)` (`benchmark/baselines.py:90,104,109`), it takes the store path explicitly. It yields stored rows oldest first, filtered to one panel name when given. It yields nothing for a missing file and never writes to the store. c1's existing functions are unchanged. The split lock is its only c3 caller.
- **Split lock.** A split is locked by the first completed stored row for that `panel_name`, using c1's `is_completed` (`benchmark/baselines.py:85-87`) [AGENT-DECIDED: alternative is to lock on any stored row, including error rows]. Every `load_panel` call reads `baselines.rows(store_path, panel_name=name)` and raises when a completed row carries a `panel_split_digest` different from the current one [AGENT-DECIDED: alternative is to check paid runs only, as the parent minimum requires]. An unchanged digest, or no completed row for that panel name, loads. There is no unlock flag; a changed split is pre-registered under a new panel `name`.
- **Contaminated panel rows in analysis (F-1).** `analyze.py` reads every row as today, except that a row carrying `panel_name` and `contaminated: true` counts as incorrect whatever its grader verdict. It stays in its task and arm denominators, and the report prints a separate per-task and per-arm `contaminated` tally. The adjustment happens once where `analyze.py` loads results (`load_results`, `benchmark/analyze.py:59`), so `correctness_pct`, `correctness_with_ci`, and `cost_per_correct` (`:180-214`) all see it. Rows without `panel_name` are unchanged. c2 guarantees only that every row carries `contaminated: bool`.
- **Committed panel and redacted rows.** `benchmark/panels/gepa-v1.json` is committed before the first paid run. Its FeatureBench members are the instances that c2's preflight admits on the cook host (the cook container can run it, since dataset, PyPI, and git reads work there), and its split is the output of `panels.stratify`. If no FeatureBench task is admitted, the panel cannot be completed, AC-7 stays red, and G-1 returns to the user instead of passing vacuously. Each gepa-v1 external member also gets a redacted copy of its dataset row, captured from the pinned revision and committed under `benchmark/tests/fixtures/panels/gepa-v1-rows/`. A redacted row keeps only `instance_id`, `repo`, `base_commit`, and the language-bearing column or columns that `external.language_of` reads.
- **No grader material in the tree (F-1).** No committed file under the tilth checkout, fixture or panel, holds a `patch`, `test_patch`, `FAIL_TO_PASS`, `PASS_TO_PASS`, or `problem_statement` value from a real dataset row. Full rows live only in `$TILTH_BENCH_DATA`, outside the checkout, as c2 requires.
- **Synthetic fixtures owned by c3 (F-1).** For the container test, c3 commits its own synthetic rows and tiny local bare repositories, not c2's fixtures and not real dataset rows. There is one under the Go slot id (language `go`, a no-dependency Go module), one under the Rust slot id (language `rust`, a no-dependency Rust crate), and one FeatureBench row (language `python`, a stdlib-only project). Each has one FAIL_TO_PASS and one PASS_TO_PASS test written for the fixture, so c2's real `prepare` and grading run on them natively with the host `go`, `cargo`, and `uv`. The test points c2's row source at a temp data directory seeded from these synthetic rows, never the host `$TILTH_BENCH_DATA`.
- **Hermetic run tests.** `run.main` panel tests do not depend on host clones. Each test creates tiny temp git repos and monkeypatches every module-level `REPOS` binding (`config.REPOS`, and `run.REPOS` imported at `benchmark/run.py:37-46`) to entries whose path and `commit_sha` point at them; `RepoConfig.path` derives from `REPOS_DIR` (`benchmark/config.py:87,104-107`). The tests also patch `gin_render_context_tasks.FIXTURE` (`benchmark/tasks/gin_render_context_tasks.py:12`) to a temp repo, and stub the model-runner launch.

## Approach

1. **Fixtures first.** Commit fixture panels under `benchmark/tests/fixtures/panels/`: one complete panel with three FeatureBench ids and the two SWE-bench Multilingual primaries, one complete panel using both fallbacks, and the malformed variants the tests parametrize. Commit c3's synthetic Go, Rust, and FeatureBench rows and bare repositories. Tests stub only `admit`, the store path, the row source, temp `REPOS` and Gin fixture repos, and the model-runner launch (F-1).
2. **Store read.** Add `baselines.rows(path, *, panel_name=None)` to `benchmark/baselines.py` as a read-only iterator over stored rows (G-1, G-2, G-3).
3. **Loader.** A new `benchmark/panels.py` holds `load_panel(path, *, store_path, admit, row_source)`. It parses the file and checks schema, family, id, fallback, and tier rules. It checks local languages against `REPOS` and external languages with `external.language_of(row_source(id))`. It computes `stratify` and `split_digest`, refuses missing required members, calls `admit` for each external member, and checks the split lock against `baselines.rows(store_path, panel_name=name)`. It returns `Panel(name, cheap, dev, test, split_digest, members)` or raises `PanelError` (G-1, G-2, G-3, F-1).
4. **Stamp and register.** `Panel.stamp(task_name)` returns the member's three stamp fields. `Panel.register(tasks)` loads external members through c2 loaders and inserts them idempotently, refusing a different task under an existing name (G-1, G-3, F-1).
5. **Run wiring.** `run.py` gains `--panel` and `--panel-split`. Inside `main`, after argument checks and before the MCP preflight, it calls `load_panel` with `RESULTS_DIR / baselines.STORE_FILENAME`, then `panel.register(TASKS)`, and sets `tasks_list` to the selected members. The cell loop adds `Panel.stamp(task_name)` to the per-cell metadata, so it reaches each row before `baselines.store`. External members run through c2 hooks with no container (F-1).
6. **c5 hand-off.** c3 fixes the `run.run_plan(cells, *, panel, ledger, candidate_sha, refreeze_baselines)` signature and the stamp and register contracts. c5 implements `run_plan` and tests its stamping. c5 `evolve.main` loads the panel only through `load_panel` with the same store path.
7. **Analysis.** `analyze.load_results` counts a contaminated panel row as incorrect and keeps it in the denominator. The report adds a per-task and per-arm contaminated tally (G-1, G-3, F-1).
8. **Commit the panel.** Run c2 preflight on the cook host, list the admitted FeatureBench Lite Level 1 instances, and fill fallbacks only for primaries whose preflight fails, recording the reason. Write `benchmark/panels/gepa-v1.json` through `panels.stratify`. Capture each external member's redacted dataset row (`instance_id`, `repo`, `base_commit`, and the language-bearing columns) from the pinned revision into `benchmark/tests/fixtures/panels/gepa-v1-rows/`, and commit both before any paid run. Commit no grader material (G-1, G-2, G-3, F-1).

## Non-goals
- Admission mechanics, native checkouts, environment builds, grading, contamination scanning, and the `contaminated` flag itself (child `bench-external-tasks`, c2).
- Applicability labels and their slicing (c4).
- `run.run_plan` itself and its stamping test, and how the evolution loop consumes tiers and splits (c5); c3 defines only the panel parameter, `Panel.stamp`, and `Panel.register` it uses.
- A panel unlock or relock flag; a changed split is a new panel name.
- Committing any real grader material (gold patch, test patch, FAIL_TO_PASS, PASS_TO_PASS, problem statement) into the tilth checkout.
- Containers of any kind (F-1).
- Changes to `src/**`, `prompts/**`, or any tilth binary behavior.
- Bumping the crate or npm version (fork law).
